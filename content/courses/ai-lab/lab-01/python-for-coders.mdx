## Blocks are indentation

There are no braces. A colon opens a block, and the block is every following line indented deeper than the line with the colon. Four spaces is the convention; mixing tabs and spaces is a `TabError`.

```python
for mark in [72, 45, 38]:
    if mark >= 50:
        print(mark, "pass")
    else:
        print(mark, "fail")
print("done")   # column 0: runs once, after the loop
```

Variables are not block-scoped. A name assigned inside an `if` or a `for` is visible after it, and a loop variable keeps its last value:

```python
for i in range(3):
    pass
print(i)             # 2
```

## Truthiness

Python's falsy values: `False`, `None`, zero of any numeric type, and every **empty** container (the empty string, list, tuple, set and dict). Everything else is truthy. JavaScript has a similar rule, with two differences that bite: an empty list is falsy in Python and truthy in JavaScript, and Python has no `undefined`.

| Value | `bool(value)` | JavaScript agrees? |
|---|---|---|
| `0`, `0.0` | False | yes |
| `""` | False | yes |
| `"0"`, `"False"` | True | yes |
| `[]` | False | **no**, `[]` is truthy in JS |
| `[0]` | True | yes |
| `None` | False | like `null` |

## `range` is half-open

`range(start, stop, step)` produces start, start + step, and so on, and stops **before** reaching stop. Two consequences: `range(n)` is exactly n values, 0 to n − 1, and a range whose stop is already behind its start is simply empty, with no error.

## `/` and `//` are different operators

`/` always gives a float, even for `6 / 2` (which is `3.0`). `//` is floor division and `%` is the matching remainder. Both round towards negative infinity. In Java, integer `/` truncates towards zero, and C and JavaScript agree with Java.

```python
print(7 / 2, 7 // 2)      # 3.5 3
print(-7 // 2, -7 % 2)    # -4 1
print(int(-7 / 2))        # -3   (truncates toward zero)
```

## Default arguments are evaluated once

This is the most famous Python bug. Click the button a few times.

<DefaultArgDemo />

```python
# the [] is built once, when def runs
def add_item(item, basket=[]):
    basket.append(item)
    return basket

print(add_item("apple"))   # ['apple']
print(add_item("mango"))   # ['apple', 'mango']   <- surprise

def add_item(item, basket=None):     # the fix: a sentinel
    if basket is None:
        basket = []
    basket.append(item)
    return basket
```

## f-strings

Prefix a string with `f`, then put an expression and an optional format spec inside the braces. You will use `.2f` constantly in the machine-learning labs.

```python
name, gpa = "Hammad", 3.456
print(f"{name} has GPA {gpa:.2f}")   # Hammad has GPA 3.46
print(f"{gpa=}")                     # gpa=3.456  (3.8+)
```

## `for ... else`

A loop can have an `else` block, and it runs only if the loop finished **without** hitting `break`. Read it as "no break". It replaces the found-flag pattern:

```python
def find_first_failing(marks):
    for name, m in marks.items():
        if m < 50:
            print("first failing:", name)
            break
    else:
        print("everyone passed")

find_first_failing({"Ali": 72, "Sara": 45, "Omar": 38})
# first failing: Sara
find_first_failing({"Ali": 72, "Sara": 65})
# everyone passed
```

## Functions return tuples, and take keywords

There is no overloading. A function can return several values, which is really one tuple that you unpack. Callers can pass arguments by name, and a bare `*` in the signature forces everything after it to be passed by name.

```python
def min_max(xs):
    return min(xs), max(xs)          # one tuple

lo, hi = min_max([4, 9, 1])          # lo = 1, hi = 9

def greet(name, greeting="Hello", *, punct="!"):
    return f"{greeting}, {name}{punct}"

greet("Sara")                        # 'Hello, Sara!'
greet("Sara", "Salam")               # 'Salam, Sara!'
greet("Sara", punct=".")             # 'Hello, Sara.'
```

<Callout type="pitfall" title="Comparisons chain">
`x == y == True` means `x == y and y == True`, not "is x == y true". The same chaining is why a range check can be written in one expression, the way it reads in maths, and why it bites when you did not mean it.
</Callout>

<Deeper kind="why" title="Why names, not variables, explain every trap above">

A Python variable is a name bound to an object, not a box that holds a value. Assignment rebinds a name and never copies. That one rule explains the mutable default (the name `basket` is bound to the same list on every call), `a is b` (two names, two objects), and why `b = a; b.append(3)` changes `a`.
