Python gives you four built-in collections, and every task in this lab comes down to picking the right one. You already know arrays and hash maps. The new parts are the two rules Python enforces about them: mutability and hashability.

<Predict
  id="tuple-mutation"
  prompt="t = ([1, 2], 3). Tuples are immutable. What happens when you run t[0].append(4), and what happens when you run t[1] = 5?"
  answer="t[0].append(4) works and t becomes ([1, 2, 4], 3). t[1] = 5 raises TypeError."
>

**`t[0].append(4)` succeeds.** The tuple is immutable, meaning its slots cannot be rebound. Slot 0 still points at the same list; you mutated the list, not the tuple. `t` is now `([1, 2, 4], 3)`.

**`t[1] = 5` raises** `TypeError: 'tuple' object does not support item assignment`. That would rebind a slot.

The consequence you will meet in a minute: this tuple cannot be a dict key or a set element, because something inside it can change.

</Predict>

## Hashable means it can be a key

Sets and dicts store items by their hash. If an object could change after it was stored, its hash would change and the table could never find it again. It is the same bug as mutating a cache key after the insert. So Python only accepts hashable objects as set elements and dict keys: numbers, strings, `None`, and tuples of hashable things. Lists, sets and dicts are rejected.

```python
{(1, 2): "ok"}   # fine: a tuple of ints
{[1, 2]: "x"}    # TypeError: unhashable type: 'list'
{([1], 2)}       # TypeError: the tuple holds a list
```

## Names point at objects; multiplication copies pointers

Assignment never copies. `a = b = []` makes two names for one list, so appending through `a` shows up in `b`. The same rule gives the most common grid bug in AI labs, where a board or maze is built with `*`:

<AliasFigure />

```python
grid = [[0] * 3] * 2
grid[0][0] = 9
print(grid)            # [[9, 0, 0], [9, 0, 0]]

grid = [[0] * 3 for _ in range(2)]
grid[0][0] = 9
print(grid)            # [[9, 0, 0], [0, 0, 0]]
```

## Dict idioms you will use every lab

```python
marks = {"Ali": 72, "Sara": 45}

marks["Omar"]                  # KeyError: 'Omar'
marks.get("Omar")              # None
marks.get("Omar", 0)           # 0

for name, m in marks.items():  # key and value together
    print(name, m)

# dict comprehension
passed = {n: m for n, m in marks.items() if m >= 50}
print(passed)                  # {'Ali': 72}
```

## Sorting and picking by a key

`sorted`, `min` and `max` take a `key` function that says what to compare. This is how you find "the student with the highest GPA" in one line, and it is the same idea as the priority in the A* frontier in week 6.

```python
students = [("Ali", 3.1), ("Sara", 3.8), ("Omar", 3.5)]

sorted(students, key=lambda s: s[1], reverse=True)
# [('Sara', 3.8), ('Omar', 3.5), ('Ali', 3.1)]

max(students, key=lambda s: s[1])      # ('Sara', 3.8)

marks = {"Ali": 72, "Sara": 45}
# iterating a dict gives its keys
max(marks, key=marks.get)              # 'Ali'
```
