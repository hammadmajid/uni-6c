Tracing is what lab exams and the midterm ask: given a graph, write the order in which nodes are expanded and the path returned. Do each one on paper first, with the frontier written out at every step. Conventions for every question here: neighbours in **alphabetical** order, goal test when a node is **taken off** the frontier, and a node that has already been reached (BFS) or expanded (DFS) is not added again.

<Predict
  id="cp-compare"
  prompt="Exam question (5 marks): compare BFS and DFS on completeness, optimality, time complexity and space complexity, and say when you would choose each."
  answer="BFS: complete, optimal for equal step costs, O(b^d) time and space. DFS: complete on finite graphs with an explored set, not optimal, O(b^m) time, O(b·m) space. BFS for the shortest path; DFS when memory is tight or solutions are deep and plentiful."
>

| | BFS | DFS |
|---|---|---|
| Complete | yes (finite branching factor) | yes on finite graphs with an explored set; no on infinite depth |
| Optimal | yes, if all step costs are equal | no |
| Time | O(b^d) | O(b^m) |
| Space | O(b^d), the whole frontier layer | O(b·m), one path plus siblings |

b = branching factor, d = depth of the shallowest goal, m = maximum depth.

**Choose BFS** when you need the fewest steps and the state space is small enough to hold a layer in memory. **Choose DFS** when memory is the constraint, when any solution will do and solutions are deep and common, or as the inner loop of iterative deepening, which gets BFS's guarantees in DFS's memory.

For full marks, define b, d and m, and give the frontier data structure for each (FIFO queue, LIFO stack).

</Predict>
