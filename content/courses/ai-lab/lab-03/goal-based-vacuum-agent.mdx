The reflex agent in the previous lesson cleans the world by tick 3 and then wastes every tick after that, because nothing it sees tells it the job is done. This lesson adds the two things the lecture's later agent types have: a **model** of the parts of the world it cannot currently see, and a **goal** it can test against that model.

**One move.** At tick 1 it sees B is clean, but its model still says A is Unknown, so the goal "everything clean" is not yet believed. It moves Left, sees A is clean, and from tick 2 onward it returns NoOp every tick.

Zero moves would need the agent to know something it never perceived. A goal-based agent acts on what it believes, and belief comes only from percepts plus the model.

## The agent now has state, so it is a class

A function forgets everything between calls. An agent with memory needs somewhere to keep it, so it becomes a class. Defining `__call__` makes an instance callable like a function, so the same `run(world, agent)` loop from the last lesson works unchanged.

```python
class GoalBasedVacuumAgent:
    def __init__(self):
        self.model = {"A": "Unknown", "B": "Unknown"}   # what it believes

    def goal_reached(self):
        return all(s == "Clean" for s in self.model.values())

    def __call__(self, percept):
        location, status = percept
        self.model[location] = status        # update the model
        if status == "Dirty":
            self.model[location] = "Clean"   # predict what Suck will do
            return "Suck"
        if self.goal_reached():
            return "NoOp"
        if location == "A":
            return "Right"
        return "Left"

run(VacuumWorld({"A": "Dirty", "B": "Dirty"}), GoalBasedVacuumAgent())
```

```text
1 ('A', 'Dirty') Suck 1
2 ('A', 'Clean') Right 2
3 ('B', 'Dirty') Suck 4
4 ('B', 'Clean') NoOp 6
5 ('B', 'Clean') NoOp 8
6 ('B', 'Clean') NoOp 10
```

Three lines map onto the lecture's vocabulary. `self.model[location] = status` is **updating internal state from the percept**. `self.model[location] = "Clean"` before returning Suck is **knowing how its own actions affect the world**. `goal_reached()` is the **goal**: a description of a desirable situation, tested explicitly.

## Three agent types, as code

| | Simple reflex | Model-based reflex | Goal-based |
|---|---|---|---|
| Looks at | current percept only | current percept and internal state | internal state and a goal |
| Python shape | a function | a class with `self.model` | a class with `self.model` and a goal test |
| Knows the job is done | never | only if a rule says so | yes, by testing the goal |
| In the vacuum world | shuttles forever | can stop, with a hand-written rule | stops when both squares are believed clean |

Strictly, the class above is a model-based agent with an explicit goal test. Russell and Norvig's full goal-based agent also **looks ahead**: it considers sequences of actions and picks one that reaches the goal. In a two-square world there is nothing to look ahead over. In a maze or a map there is, and finding that sequence is exactly what BFS and DFS do in lab 04.

<Callout type="exam" title="Lecture phrasing to reproduce">
The slides: "Reflex agent breaks when it sees brake lights. Goal based agent reasons: brake light → car in front is stopping → I should stop → I should use brake." In a lab viva, point at `goal_reached()` and say the goal is explicit, so it can be changed without rewriting the rules. That flexibility is the slide's main claim for goal-based agents.
</Callout>

<Deeper kind="edge" title="Fixing the stale model">

Two standard fixes. **Forget over time:** after k ticks without seeing a square, reset its belief to Unknown, which sends the agent back to look. **Model the dynamics:** if dirt appears with probability p per tick, the agent should expect a square to be dirty after roughly 1/p ticks and revisit on that schedule. The second is a utility-based agent: it trades the cost of a move against the expected dirt it removes. That is the fourth agent type in lecture 2.

</Deeper>
