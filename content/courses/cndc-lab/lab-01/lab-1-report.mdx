<Predict
  id="why-before-http"
  prompt="Explain, in order, every exchange your laptop had to complete before it could send the HTTP GET, and which layer each one belongs to. (4 marks)"
  answer="ARP request and reply to learn the router's MAC address (link layer). DNS query and response to translate gaia.cs.umass.edu to 128.119.245.12 (application layer, over UDP). TCP three-way handshake SYN, SYN-ACK, ACK with 128.119.245.12 port 80 (transport layer). Only then the GET (application layer, over TCP). Every step needs the result of the one before it."
>

1. **ARP** (link): the laptop must put the router's MAC address on the frame, because gaia is not on the local link. It broadcasts "who has 192.168.1.1" and the router replies. Frames 1 and 2.
2. **DNS** (application, over UDP): the browser has a name, IP needs an address. A query for gaia.cs.umass.edu goes to the router's resolver and comes back with 128.119.245.12. Frames 7 to 10.
3. **TCP handshake** (transport): SYN to port 80, SYN-ACK back, ACK. No data yet; this only agrees sequence numbers and options. Frames 11 to 13, and the SYN-ACK takes a full round trip.
4. **HTTP GET** (application, over TCP): frame 14, the first packet with anything the user asked for.

Each step is blocked on the previous one, which is why a first page load is slower than a reload: on the reload, the ARP cache, the DNS cache and often the TCP connection itself are all still warm.

</Predict>
