## Long answers

<Predict
  id="cp-trace-login"
  prompt="Trace what happens, from the click to the page, when a user submits the login form (method post, action login) of an app deployed at /demo. Name the HTTP request, the Tomcat steps and the servlet methods. (6 marks)"
  answer="Browser builds POST /demo/login with a urlencoded body userid=...&password=..., opens or reuses a TCP connection to localhost:8080, sends it. Tomcat's connector hands it to a pool thread, parses it into HttpServletRequest, selects the /demo context, matches /login to LoginServlet, calls service(), which calls doPost. doPost reads getParameter(userid/password), checks them, writes HTML to the response. Tomcat sends a 200 response; the browser renders it."
>

1. **Browser.** The form's action `login` resolves against the page's URL to `/demo/login`. The browser sends `POST /demo/login HTTP/1.1` with `Host: localhost:8080`, `Content-Type: application/x-www-form-urlencoded`, an empty line, and the body `userid=ali&password=123`, over a TCP connection to port 8080.
2. **Connector.** Tomcat's HTTP connector accepts the connection and gives the request to a worker thread from its pool.
3. **Context.** Tomcat parses the bytes into an `HttpServletRequest` and `HttpServletResponse`, and picks the webapp whose context path prefixes the path: `/demo`.
4. **Mapping.** The remaining path `/login` exactly matches the LoginServlet's mapping.
5. **Servlet.** The container calls `service(request, response)` on the single LoginServlet instance. It sees POST and calls `doPost`. `doPost` reads `request.getParameter("userid")` and `"password"` into local variables, compares them with the stored credentials, and writes HTML through `response.getWriter()`.
6. **Response.** Tomcat sends `HTTP/1.1 200` with the headers and the HTML body. The browser renders it.

</Predict>

<Predict
  id="cp-write-servlet"
  prompt="Write a servlet mapped to /greet that reads name and age from a GET request (for example /demo/greet?name=Ali&age=21) and responds with an HTML heading 'Ali is 21'. If name is missing, respond 'Who are you?'. (5 marks)"
  answer="@WebServlet(&quot;/greet&quot;) class extending HttpServlet, overriding doGet; String name = request.getParameter(&quot;name&quot;), String age = request.getParameter(&quot;age&quot;); setContentType text/html; if name == null print Who are you? else print the heading with name and age via response.getWriter()."
>

```java
import java.io.IOException;
import java.io.PrintWriter;

import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

@WebServlet("/greet")
public class GreetServlet extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response) throws IOException {
        String name = request.getParameter("name");   // locals, never fields
        String age = request.getParameter("age");

        response.setContentType("text/html;charset=UTF-8");
        PrintWriter out = response.getWriter();
        out.println("<html><body>");
        if (name == null) {
            out.println("<h1>Who are you?</h1>");
        } else {
            out.println("<h1>" + name + " is " + age + "</h1>");
        }
        out.println("</body></html>");
    }
}
```

Marks usually go to: the annotation with the right path (1), extending HttpServlet and overriding **doGet** because the request is GET (1), getParameter with names matching the query string exactly (1), the null check (1), and setContentType plus getWriter to write the response (1). Beyond the marks: in real code, escape `name` before writing it into HTML, or a user can inject a script.

</Predict>

<Predict
  id="cp-dev-vs-deploy"
  prompt="Slides 25 to 29 contrast the development view with the server's view. Explain the difference and how one becomes the other. (4 marks)"
  answer="Development view is IntelliJ's Maven project: src/main/java for Java source, src/main/resources, src/main/webapp for web files and WEB-INF/web.xml, pom.xml for dependencies. The build compiles the Java into WEB-INF/classes, copies webapp files to the root, puts dependency jars in WEB-INF/lib, and zips it into a WAR in target/. Deployed into Tomcat's webapps, the WAR is expanded into the standard webapp layout the server understands, with the file name as the context path."
>

- **Development view** (slide 26): the IntelliJ Maven project. Java sources in `src/main/java`, web files in `src/main/webapp` (including `WEB-INF/web.xml`), dependencies declared in `pom.xml`, tests in `src/test`.
- **Build**: compiles sources into `WEB-INF/classes`, copies `src/main/webapp` to the archive's root, copies compile-scope dependency jars into `WEB-INF/lib`, leaves tests and provided-scope jars (the servlet API) out, and zips the result into `target/demo.war`.
- **Server view** (slide 29): the WAR is placed in Tomcat's `webapps/`, expanded into `webapps/demo/`, and served at context path `/demo`: public files at the root, private WEB-INF beside them.
- The point: you edit the development view, and Tomcat only understands the server view. The WAR is the artifact that carries one into the other.

</Predict>
