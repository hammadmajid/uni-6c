## Sending parameters with GET: the query string

Slide 45: parameters ride in the URL after a `?`, as `name=value` pairs separated by `&`:

```
http://localhost:8080/demo/hello-servlet?name=ali&password=123&age=23
```

Values are percent-encoded: a space becomes `+` or `%20`, and `&` inside a value becomes `%26`, so it cannot be mistaken for a separator. The browser encodes a form for you. If you build a query string by hand, you must encode it yourself.

## Receiving them: getParameter

```java
String name = request.getParameter("name");         // "ali"
String password = request.getParameter("password"); // "123"
String missing = request.getParameter("email");     // null: absent
```

Three rules cover every surprise on slides 47 to 58:

1. **The same call reads GET and POST.** For GET the container parses the query string; for a form POST it parses the request body (`application/x-www-form-urlencoded`). Your code does not change.
2. **Names are case-sensitive and must match the form's `name` attribute exactly.** `name` is not `Name`.
3. **A missing parameter is `null`, not an empty string.** An empty text box that was submitted gives `""`.

## GET or POST is HTTP's decision, not the servlet's

`doGet` and `doPost` are just two methods the container picks between by reading the request line. Nothing stops you from deleting database rows in `doGet`. What stops you is HTTP's definition of the methods (RFC 9110):

| | GET | POST |
|---|---|---|
| Meaning | retrieve a representation; **safe** (no side effects the user asked for) and **idempotent** | process the enclosed data; may change server state; not idempotent |
| Parameters | in the URL, so in history, bookmarks, server access logs, Referer headers | in the body, not in the URL |
| Caching and prefetch | browsers and proxies may cache, prefetch, and retry it | never cached by default; the browser warns before resending |
| Size | limited by URL length (about 8 KB in practice) | effectively unlimited |
| Use for | search, filters, pagination, viewing a record | login, registration, placing an order, uploads |

<Deeper kind="edge" title="Things that bite later">

- **Checkboxes and multi-selects** send the same name several times (`course=CS&course=AI`). `getParameter` returns only the first; use `getParameterValues("course")`.
- **Non-English input.** Call `request.setCharacterEncoding("UTF-8")` before the first `getParameter` if a POST body may carry Urdu or accented names, or set `request-character-encoding` in web.xml once for the whole app.
- **Handling both methods.** A common idiom is a doPost that just calls `doGet(request, response)`. Convenient, but it tells the world the two are interchangeable, which HTTP says they are not.
- **Refresh after POST** makes the browser offer to resend the form. The standard fix is Post/Redirect/Get: doPost does the work, then `response.sendRedirect(...)` to a GET page.

</Deeper>
