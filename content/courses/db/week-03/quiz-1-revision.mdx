<Predict
  id="q1-long-characteristics"
  prompt="Explain four characteristics of the database approach that distinguish it from file processing, with one example each. (8 marks)"
  answer="Self-describing (catalog); insulation between programs and data (program–data independence through the three-schema architecture); multiple views; sharing with multi-user transaction processing (concurrency control, ACID)."
>

**Model answer.**

1. **Self-describing nature.** The database stores its own definition (metadata) in the DBMS catalog. Example: the column `phone varchar(15) NOT NULL` is recorded in the catalog, not hard-coded in every program.
2. **Insulation between programs and data (data abstraction).** Programs do not depend on how data is stored, so storage can change underneath them. Example: adding an index changes no program (physical independence), and adding a column changes none that name their columns (logical independence).
3. **Multiple views.** Each user group sees only the subset it needs. Example: finance sees fee records, a student sees only their own grades.
4. **Sharing and multi-user transaction processing.** Concurrency control keeps simultaneous updates correct, and transactions are ACID. Example: an ATM withdrawal and a mobile deposit on the same account do not overwrite each other.

Two marks per point: one for the idea, one for the example.

</Predict>

<Predict
  id="q1-long-scenario"
  prompt="A pharmacy chain with 12 branches keeps each branch's stock in its own spreadsheet. Head office cannot tell how many units of a medicine exist in total, and two branches sometimes promise the same delivery. Would a DBMS help? Justify with three features. (4 marks)"
  answer="Yes: one shared database removes redundancy and inconsistency, concurrency control and transactions stop double-promising, and queries over the whole database give totals; add views and security per branch."
>

**Model answer.** Yes, a DBMS is justified: many users, shared data, and the structure will keep growing.

- **One shared database** replaces 12 copies, which removes the **redundancy and inconsistency**. Head office gets the total with one query.
- **Concurrency control and transactions** (isolation) stop two branches from reserving the same stock at the same moment.
- **Multiple views and access control** let each branch see its own stock while head office sees everything.
- Also credit **backup and recovery**, and **integrity constraints** such as stock never going below zero.

Three justified features plus a verdict is full marks.

</Predict>
